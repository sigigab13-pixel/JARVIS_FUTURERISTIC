# Contributing to JARVIS

Thank you for your interest in JARVIS.

JARVIS is an actively developing independent AI assistant platform. Contributions, testing, ideas, documentation, and constructive feedback are welcome.

## Before contributing

Please:

1. Read the project README.
2. Check existing issues before opening a new one.
3. Keep changes focused and easy to review.
4. Never commit API keys, OAuth secrets, passwords, tokens, or other private credentials.
5. Clearly explain what your change does and why it is useful.

## Ways to contribute

### 🐛 Report a bug

Open an issue and include:

- What happened
- What you expected to happen
- Steps to reproduce it
- Browser/device information when relevant
- Screenshots or non-sensitive logs when useful

### 💡 Suggest a feature

Describe:

- The problem or use case
- Your proposed solution
- How the feature would fit into JARVIS
- Any limitations or trade-offs you can identify

### 💻 Submit code

When submitting a code contribution:

1. Keep the change focused.
2. Follow the existing project structure.
3. Avoid unrelated refactoring.
4. Add or update tests when appropriate.
5. Check that sensitive values are not included.
6. Explain important architectural decisions in the pull request.

## Security

Do not publish credentials or private security information in issues or pull requests.

For security concerns, follow the instructions in [SECURITY.md](SECURITY.md).

## Development direction

JARVIS is being developed in stages. Current priorities include orchestration, capability execution, realtime communication, testing, integrations, and the Forest content engine.

Large architectural changes should be discussed before implementation when possible.

## Code of conduct

Be respectful, constructive, and patient with other contributors.

The goal is to build useful technology together.

Thank you for helping JARVIS grow.
